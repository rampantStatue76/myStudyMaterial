### 工作区、暂存区、版本库的区别

1. 电脑里面里面能看见目录的直接编辑文件地方
2. 暂存区就是用于存放临时改动的地方，使用add .指令将工作区的改动添加到这里
3. 存放历史改动的地方，同意git commit将暂存区的内容保存到版本库，形成提交记录

### 分支管理

**分支命名：feature（新功能开发）、bugfix（问题描述）、hotfix（紧急修复）**

**主分支：master     新功能分支：feature**

- git branch：查看所有分支

- git branch feature-login：创建新分支feature-login但不会立即切换

- git checkout feature-login：切换到feature-login分支

- git checkout -b feature-login：创建feature-login分支并立即切换到该分支（-b的意思就是branch）
- git switch feature-login：切换到feature-login分支

**合并分支：**

- 切换到目标分支（主分支master）：git switch master或者git checkout master
- 在目标分支上执行合并：git merge feature-login
- 删除分支git branch -d feature-login

**解决合并冲突：**

- 查看冲突文件
- 手动编辑解决
- 添加到暂存区
- 完成合并提交

### git pull和git fetch区别

git pull拉取远程代码的同时会自动执行merge操作：自动合并到本地工作区，但是fetch不会，fetch需要自己去手动合并

推荐在团队合作中：先使用git fetch检查一下远程有什么更新，确认无误后再使用gir merge，这样更安全

### git merge与git rebase使用

要把分支代码合并到主分支，如果使用merge，在git图形中会保留分支结构与时间顺序，分支结构就会变得很乱，很庞大，所以引入了rebase。

在主分支上执行git rebase develop操作，就不会保留分支结构，整个分支结构就只有一条线

### git stash使用场景

stash操作可以将当前分支中的暂存区和工作区中的改动文件保存到git栈里面，需要的时候再取出来。

场景1：在当前分支上进行开发时，需要切换到另外一个分支上进行开发，但是git不允许你切换，因为当前分支的变动代码哈没有提交，此时可以先将这些代码先提交了再切换分支，也可以先把当前分支的代码存到git stash栈中，切换到其他分支工作完毕后在切换回之前的分支把存起来的代码使用git stash pop取出来。

场景2：一般在push代码之前我们都需要pull拉一下远程最新代码（为了避免其他同事和我同时修改了某个文件，但是同事比我先push他的修改到远程仓库，此时我再提交上去就可能出现远程冲突），但是这种情况下远程是不会让我拉的，因为我本地的修改还没有提交，此时我们就可以先git stash把未提交的改动存到git栈里面，然后把远程的代码拉下来，再把栈里面的代码取出来，在本地中修改冲突后再commit push代码，这样就不会造成在远端合并到时候造成冲突了。
