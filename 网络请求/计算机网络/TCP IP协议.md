## 总结

TCP/IP 是一套网络通信协议体系，分为四层：应用层、传输层、网络层、链路层

IP 负责寻址与路由，TCP提供可靠的、面向连接的数据传输

TCP 通过“三次握手”建立连接，“四次挥手”断开连接，保证消息不丢失、有序、不乱序

## TCP与IP关系

IP：负责把数据包送到目标地址

TCP：确保数据包安全、顺利、完整地送达

## TCP/IP四层模型

- **应用层：** 为用户提供网络服务（网页、邮件、文件传输）
  代表协议: HTTP、HTTPS、WebSocket
- **传输层：** 负责端到端通信（确保消息可靠性和顺序）
  代表协议: TCP、UDP
- **网络层：** 负责寻址和路由（确定数据包去哪）
  代表协议：IP
- **链路层：** 负责物理传输（数据变成电信号或无线信号）

## TCP的三次握手、四次挥手

**握手：** 目的是确保双方都准备好通信，并且能互相确认对方的收发能力

|    步骤    | 谁发送给谁         | 内容      | 说明               |
| :--------: | ------------------ | :-------- | ------------------ |
| 第一次握手 | 客户端 ---> 服务端 | SYN       | 我要连接你了       |
| 第二次握手 | 服务端 ---> 客户端 | SYN + ACK | 好的，我准备好了   |
| 第三次握手 | 客户端 ---> 客户端 | ACK       | 收到确认，开始通信 |

**挥手：**TCP是**双向通道**，所以断开需要两边都说“我关了”

| 步骤       | 谁发送给谁         | 内容 | 说明           |
| ---------- | ------------------ | ---- | -------------- |
| 第一次挥手 | 客户端 ---> 服务端 | FIN  | 我要断开了     |
| 第二次挥手 | 服务端 ---> 客户端 | ACK  | 好的，我知道了 |
| 第三次挥手 | 服务端 ---> 客户端 | FIN  | 我也要断开了   |
| 第四次挥手 | 客户端 ---> 服务端 | ACK  | 确认断开       |

## TCP vs UDP

| 特性     | TCP                        | UDP              |
| -------- | -------------------------- | ---------------- |
| 连接方式 | 三次握手                   | 直接发           |
| 可靠性   | 保证数据完整、有序、不丢失 | 不保证、可能丢包 |
| 速度     | 较慢                       | 很快             |
